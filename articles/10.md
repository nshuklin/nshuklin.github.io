# Тема 10. Маршрутизация и управление состоянием: Vue Router и Pinia


## Аннотация

Одностраничное приложение без маршрутизации — это книга, в которой одна страница на всё содержание. В этой теме мы научим приложение «ходить по страницам» с помощью Vue Router: динамические маршруты, ленивая загрузка компонентов и навигационные хуки (guards), охраняющие приватные разделы. Вторая половина темы — Pinia, официальный менеджер состояния (state manager) Vue: сторы (stores), геттеры, действия и плагины, включая персистентность в `localStorage`. К концу занятия у приложения появятся страницы, защита маршрутов и профиль пользователя, переживающий перезагрузку страницы.

## Цель темы

**Цель:** освоить навигацию и глобальное хранилище состояния.

После изучения темы вы будете знать/уметь:

- знать, как Vue Router сопоставляет URL с компонентами, зачем нужны динамические маршруты и ленивая загрузка;
- знать виды навигационных хуков (guards) и уметь защищать маршруты через `meta.requiresAuth`;
- уметь создавать Pinia-сторы в синтаксисе Setup stores и Options stores, писать getters и actions;
- уметь применять `$patch`, `$subscribe` и `storeToRefs`;
- уметь подключать плагины Pinia (персистентность в `localStorage`).

## Теоретическая часть

### 10.1. Зачем SPA нужен роутер. Базовые понятия Vue Router

В одностраничном приложении (Single Page Application, SPA) страница не перезагружается, но у пользователя сохраняется законное ожидание: URL должен отражать то, что он видит, кнопки «назад»/«вперёд» — работать, а ссылкой на конкретный экран можно поделиться. Маршрутизатор (router) решает именно это: сопоставляет URL с компонентами и управляет историей через History API браузера — без перезагрузки страницы.

Минимальная настройка Vue Router 4:

```ts
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '@/views/HomeView.vue'

export const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', name: 'home', component: HomeView },
    { path: '/login', name: 'login', component: () => import('@/views/LoginView.vue') },
  ],
})
```

```ts
// src/main.ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import { router } from './router'

const app = createApp(App)
app.use(createPinia())
app.use(router)
app.mount('#app')
```

В шаблоне появляются два компонента:

```vue
<template>
  <nav>
    <RouterLink to="/">Главная</RouterLink>
    <RouterLink :to="{ name: 'login' }">Вход</RouterLink>
  </nav>
  <RouterView /> <!-- сюда рендерится компонент текущего маршрута -->
</template>
```

**Динамические маршруты** (dynamic routes) описываются параметрами в пути:

```ts
{
  path: '/projects/:projectId',
  name: 'project-board',
  component: () => import('@/views/ProjectBoardView.vue'),
  props: true, // params придут в компонент как props
  meta: { requiresAuth: true, title: 'Доска проекта' },
}
```

При открытии `/projects/my-project` параметр `projectId` станет `'my-project'`. В компоненте его можно принять через props (`defineProps<{ projectId: string }>()`) или прочитать из `useRoute()`:

```ts
import { useRoute } from 'vue-router'

const route = useRoute()
const projectId = computed(() => route.params.projectId as string)
```

> 💡 `useRoute()` возвращает реактивный объект текущего маршрута, `useRouter()` — сам роутер для программной навигации (`router.push`, `router.replace`, `router.back()`). В компонентах используйте эти функции; «магический» `this.$router` остался в Options API.

### 10.2. Ленивая загрузка маршрутов

Если подключать все экраны статическими импортами, пользователь при первом заходе скачает всё приложение целиком — включая канбан, настройки и страницу, которую, возможно, никогда не увидит. Ленивая загрузка (lazy loading) решает это динамическим импортом (dynamic import):

```ts
routes: [
  { path: '/projects', component: () => import('@/views/ProjectsView.vue') },
]
```

Работает это так:

1. сборщик (Vite/Rollup) видит `import(...)` и выносит модуль в **отдельный чанк** (chunk) — отдельный файл JavaScript;
2. в основной бандл попадает только обещание (Promise) загрузить этот файл;
3. при первой навигации на маршрут роутер вызывает `import()`, дожидается загрузки чанка и рендерит компонент;
4. повторная навигация использует уже загруженный модуль из кэша.

```ts
// экран с «вежливым» плейсхолдером на время загрузки чанка
import { defineAsyncComponent } from 'vue'

const ProjectsView = defineAsyncComponent({
  loader: () => import('@/views/ProjectsView.vue'),
  loadingComponent: SkeletonView,
})
```

> ⚠️ Ленивая загрузка — не догма. Экран входа и главный макет разумно оставить в основном бандле, чтобы первый значимый кадр (first paint) не ждал второй запрос. Микро-чанки по 2 КБ тоже не подарок: HTTP-запросы не бесплатны.

### 10.3. Навигационные хуки (guards)

Навигационные хуки (navigation guards) — контролёры, которые могут разрешить, перенаправить или отменить переход. У них три уровня:

| Уровень | Где объявляется | Типичное применение |
|---|---|---|
| глобальный | `router.beforeEach(...)` | проверка авторизации, заголовок страницы |
| на маршрут | поле `beforeEnter` в записи маршрута | правила конкретного экрана |
| в компоненте | `onBeforeRouteLeave`, `onBeforeRouteUpdate` | «сохранить черновик перед уходом?» |

Во Vue Router 4 хук **возвращает** решение вместо вызова колбэка `next()` (старый стиль из Router 3):

```ts
router.beforeEach((to) => {
  const auth = useAuthStore() // Pinia уже установлен к моменту навигации

  if (to.meta.requiresAuth && !auth.isAuthenticated) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }
  // undefined / true — разрешить переход; false — отменить
})
```

Возможные возвращаемые значения: `undefined`/`true` (разрешить), `false` (отменить), объект маршрута (перенаправить), имя/путь. Хуки поддерживают `async` — можно дождаться проверки токена на сервере.

Поле `meta` — произвольные метаданные маршрута, доступные через `to.meta` и `route.meta`. Важный нюанс: **meta не наследуется автоматически**. Для вложенных маршрутов проверяйте всю цепочку совпавших записей:

```ts
const requiresAuth = to.matched.some((record) => record.meta.requiresAuth)
```

### 10.4. Pinia: зачем нужен отдельный менеджер состояния

Composables отлично переиспользуют логику, но у каждого вызова — своё состояние. Когда состояние должно быть **общим** (текущий пользователь, список проектов, тема оформления), его выносят в глобальное хранилище. Официальное решение экосистемы Vue — Pinia (произносится примерно как «пинья», по-испански — ананас: сторы держат состояние, как кожура держит мякоть).

Стор (store) — реактивный контейнер с состоянием (state), производными значениями (getters) и методами изменения (actions):

```ts
// src/stores/auth.ts — Setup store
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export interface User {
  id: number
  name: string
  email: string
}

export const useAuthStore = defineStore('auth', () => {
  // state
  const token = ref('')
  const user = ref<User | null>(null)

  // getters
  const isAuthenticated = computed(() => token.value !== '')

  // actions
  function setSession(newToken: string, newUser: User): void {
    token.value = newToken
    user.value = newUser
  }

  function logout(): void {
    token.value = ''
    user.value = null
  }

  return { token, user, isAuthenticated, setSession, logout }
})
```

Тот же стор в синтаксисе Options store:

```ts
export const useAuthStore = defineStore('auth', {
  state: () => ({
    token: '',
    user: null as User | null,
  }),
  getters: {
    isAuthenticated: (state) => state.token !== '',
  },
  actions: {
    setSession(newToken: string, newUser: User): void {
      this.token = newToken
      this.user = newUser
    },
    logout(): void {
      this.token = ''
      this.user = null
    },
  },
})
```

| Критерий | Setup store | Options store |
|---|---|---|
| Синтаксис | как `<script setup>`: `ref`, `computed`, функции | объект с `state`/`getters`/`actions` |
| Типизация TS | естественная, вывод типов | хорошая, но больше «магии» с `this` |
| Гибкость | любые composables, watch, локальные переменные | только предопределённые секции |
| `$reset()` | нет (реализуется вручную) | есть из коробки |
| Рекомендация | **по умолчанию в курсе** | когда привычнее объектный стиль |

Использование в компоненте:

```ts
import { storeToRefs } from 'pinia'
import { useAuthStore } from '@/stores/auth'

const auth = useAuthStore()

// реактивные поля — через storeToRefs, иначе реактивность потеряется!
const { isAuthenticated, user } = storeToRefs(auth)
// действия — просто деструктуризацией
const { logout } = auth
```

> ⚠️ Классическая ошибка: `const { isAuthenticated } = useAuthStore()` — деструктуризация достаёт **значение**, а не связь с хранилищем, и реактивность исчезает. Это «деструктуризация reactive» из темы 9, только в масштабе приложения. `storeToRefs` существует ровно для этого.

**`$patch`** применяет несколько изменений одной операцией:

```ts
auth.$patch({ token: '', user: null })
// или функцией — для сложных мутаций
auth.$patch((state) => {
  state.token = ''
  state.user = null
})
```

Это атомарно: подписчики получат одно уведомление вместо двух, а в DevTools изменение отобразится одной записью.

**`$subscribe`** подписывается на любые изменения состояния стора — из какого бы места приложения они ни пришли:

```ts
auth.$subscribe(
  (_mutation, state) => {
    localStorage.setItem('app-auth', JSON.stringify(state))
  },
  { detached: true }, // переживёт размонтирование компонента-подписчика
)
```

Именно на `$subscribe` чаще всего строится персистентность (сохранение состояния между перезагрузками).

### 10.5. Плагины Pinia

Плагин (plugin) Pinia — функция, вызываемая при создании каждого стора; точка расширения для персистентности, логирования, валидации:

```ts
import type { PiniaPluginContext } from 'pinia'

export function localStoragePlugin({ store }: PiniaPluginContext): void {
  const key = `app:${store.$id}`

  const saved = localStorage.getItem(key)
  if (saved !== null) {
    store.$patch(JSON.parse(saved) as Record<string, unknown>)
  }

  store.$subscribe((_mutation, state) => {
    localStorage.setItem(key, JSON.stringify(state))
  })
}

// main.ts
const pinia = createPinia()
pinia.use(localStoragePlugin)
app.use(pinia)
```

Плагин получает контекст стора (`store`, `options`, `pinia`) и может добавлять новые свойства и методы, доступные во всех сторах. Для продакшена чаще берут готовый `pinia-plugin-persistedstate`, но написать свой учебный плагин — лучший способ понять, как устроены и готовые.

> 💡 Сторы Pinia ленивы: стор «оживает» при первом вызове `useXStore()`. Поэтому вызывать `useAuthStore()` внутри навигационного хука безопасно — но только после `app.use(pinia)`, иначе Pinia не знает, к какому приложению относится стор.

**Реализовать систему хлебных крошек (breadcrumbs) на основе метаданных роутов.**

Состав:

1. Каждому маршруту приложения добавьте в `meta` поле `title` («Главная», «Проекты», название проекта, «Задача #N»).
2. Компонент `Breadcrumbs.vue`:
   - строит цепочку из `route.matched`, фильтруя записи с `meta.title`;
   - рендерит ссылки через `<RouterLink>`; последний элемент — обычный текст (текущая страница);
   - разделители между крошками (например, `›`).
3. Разместите компонент над `<RouterView />`; проверьте цепочку на вложенном маршруте `/projects/:projectId/tasks/:taskId` (экран задачи можно временно заглушить).
4. Для динамического сегмента «Задача #N» подставляйте реальный номер из `route.params`.

### Требования к сдаче

- TypeScript strict без ошибок; компонент не содержит хардкода маршрутов — только `route.matched` и `meta`;
- переход по любой крошке ведёт на соответствующий экран;
- коммиты по Conventional Commits.

### Критерии оценки

1. Корректная цепочка из `route.matched` на вложенных маршрутах (до 3 баллов).
2. Последний элемент без ссылки, разделители, аккуратная типографика (до 2 баллов).
3. Динамический подстановщик «Задача #N» из params (до 2 баллов).
4. Типизация `meta` (интерфейс `RouteMeta` через module augmentation) (до 2 баллов).
5. Сверх ожиданий: копирование ссылки на задачу по клику на последнюю крошку (до 1 балла).

## Типичные ошибки и заблуждения

1. **Деструктуризация стора без `storeToRefs`** — компонент получает «мёртвые» значения и перестаёт реагировать на изменения хранилища.
2. **Привычка `next()` из Vue Router 3.** В Router 4 решение хука возвращается (`return false`, `return { name: 'login' }`); смешение стилей приводит к двойным переходам и трудноуловимым багам.
3. **Ожидание, что `meta` наследуется детьми.** Мета принадлежит конкретной записи маршрута; для вложенных маршрутов проверяйте `to.matched.some(...)`.
4. **Стор-«бог»**: одно хранилище на всё приложение. Разумная гранулярность — стор на доменную область: `auth`, `projects`, `tasks`, `profile`.
5. **Ленивая загрузка всего подряд**, включая экран входа и корневой макет: первый кадр начинает ждать дополнительные запросы.
