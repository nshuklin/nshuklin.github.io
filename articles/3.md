## Теоретическая часть

### 2.1. Области видимости и замыкания

Начнём с областей видимости (scope) — правил, по которым код «видит» переменные.

В современном JS переменные объявляются тремя способами с разной семантикой:

| Ключевое слово | Область видимости | Повторное объявление | Особенности |
| --- | --- | --- | --- |
| `var` | Функциональная | Допустимо | Всплытие (hoisting), игнорирует блоки `{}` |
| `let` | Блочная | Ошибка | Можно переприсваивать |
| `const` | Блочная | Ошибка | Нельзя переприсваивать (но содержимое объектов менять можно) |

Ключевое отличие: `var` «не видит» фигурных скобок циклов и условий, `let` и `const` видят. Именно поэтому классический код с `var` внутри цикла ломает ожидания:

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Выведет: 3, 3, 3 — все колбэки видят одну и ту же переменную i

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Выведет: 0, 1, 2 — для каждой итерации создаётся своя i
```

**Замыкание (closure)** — это функция вместе с лексическим окружением (lexical environment), в котором она была создана. Проще говоря: функция запоминает переменные того места, где её объявили, и продолжает иметь к ним доступ даже после того, как внешняя функция завершила работу. Переменные, грубо говоря, упаковываются в невидимый рюкзак и путешествуют вместе с функцией.

```js
function createCounter(initial = 0) {
  let count = initial; // приватная переменная

  return {
    increment: () => ++count,
    decrement: () => --count,
    value: () => count,
  };
}

const counter = createCounter();
counter.increment();
counter.increment();
console.log(counter.value()); // 2
console.log(counter.count);   // undefined — снаружи count не достать
```

Функции `increment`, `decrement` и `value` «унесли с собой» переменную `count` из завершившегося `createCounter`. Никакого другого способа объявить по-настоящему приватную переменную в классическом JS не существовало — замыкания долгое время играли роль модификатора `private`.

Практический пример из жизни UI — **debounce** (отложенное выполнение): поиск в TaskFlow не должен отправлять запрос на каждую нажатую букву.

```js
function debounce(fn, delayMs) {
  let timerId; // живёт в замыкании между вызовами
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), delayMs);
  };
}

const searchTasks = debounce((query) => {
  console.log(`Ищем задачи по запросу: ${query}`);
}, 300);

searchTasks('д');      // отменён следующим вызовом
searchTasks('де');     // отменён следующим вызовом
searchTasks('дед');    // выполнится через 300 мс
```

Обратите внимание: `timerId` хранится между вызовами возвращённой функции, но снаружи недоступен. Это и есть замыкание в работе — состояние без объектов и классов.

> 💡 Полезно знать: замыкания — не «фича для собеседований», а рабочая лошадка фронтенда. Хуки Vue и React внутри устроены на замыканиях, мемоизация, фабрики компонентов, модульный паттерн — всё это они же.

> ⚠️ Частая ошибка: ожидать, что замыкание «замораживает» значение переменной. Оно даёт доступ к самой переменной, а не к её копии на момент создания функции. Поэтому в примере с `var` все колбэки увидели финальное `i === 3`: переменная одна, и к моменту срабатывания таймеров цикл её уже изменил.

### 2.2. Контекст `this`

`this` — это ссылка на объект-контекст, с которым вызывается функция. Главная особенность: **в обычных функциях `this` определяется не местом объявления, а способом вызова** (динамический контекст). Отсюда классическое: «`this` — это хамелеон, который меняет окраску в зависимости от того, кто его вызвал».

Четыре правила определения `this` в порядке приоритета:

1. **Вызов через `new`** — `this` указывает на создаваемый объект.
2. **Явная привязка** (`call` / `apply` / `bind`) — `this` задаётся аргументом.
3. **Вызов как метод объекта** (`obj.method()`) — `this` указывает на объект слева от точки.
4. **Простой вызов** (`fn()`) — в строгом режиме `this === undefined`, иначе глобальный объект.

```js
const board = {
  name: 'Спринт 5',
  describe() {
    return `Доска «${this.name}»`;
  },
};

board.describe();        // this = board → «Доска „Спринт 5“»

const describe = board.describe;
describe();              // простой вызов: this = undefined → TypeError

board.describe.call({ name: 'Бэклог' }); // явная привязка → «Доска „Бэклог“»
```

**Стрелочные функции** своего `this` не имеют — они забирают его из лексического окружения, где объявлены (как обычную переменную). Это делает их идеальными для колбэков внутри методов:

```js
const taskBoard = {
  name: 'TaskFlow',
  tasks: ['Деплой', 'Тесты'],
  printTasks() {
    // стрелочная функция берёт this из printTasks, то есть board
    this.tasks.forEach((task) => {
      console.log(`${this.name}: ${task}`);
    });
  },
};

taskBoard.printTasks();
// TaskFlow: Деплой
// TaskFlow: Тесты
```

Будь внутри `forEach` обычная `function`, её `this` стал бы `undefined` (в strict mode), и код упал бы. До ES6 эту проблему решали костылём `const self = this` — теперь он нужен только при чтении старого кода.

**Явная привязка контекста** — три метода, которые есть у каждой функции:

| Метод | Что делает | Аргументы | Когда использовать |
| --- | --- | --- | --- |
| `fn.call(ctx, a, b)` | Вызывает `fn` немедленно | Список через запятую | Известен точный набор аргументов |
| `fn.apply(ctx, [a, b])` | Вызывает `fn` немедленно | Массив аргументов | Аргументы уже в массиве |
| `fn.bind(ctx, a)` | Возвращает **новую** функцию | Любые; фиксируются на будущее | Передать метод как колбэк, не теряя контекст |

`bind` отличается принципиально: он не вызывает функцию, а создаёт обёртку с навсегда пришитым контекстом.

```js
const taskService = {
  prefix: '[TaskFlow]',
  log(message) {
    console.log(`${this.prefix} ${message}`);
  },
};

setTimeout(taskService.log, 100);                    // 💥 this потерян
setTimeout(taskService.log.bind(taskService), 100);  // ✅ [TaskFlow] Задача создана

// Альтернатива — стрелочная функция-обёртка:
setTimeout(() => taskService.log('Задача создана'), 100);
```

> ⚠️ Частая ошибка: «привязывать» стрелочные функции. `arrow.bind(ctx)` не сделает ничего полезного — у стрелки нет собственного `this`, и привязка игнорируется. Если нужен управляемый `this`, используйте обычную функцию или метод объекта.

### 2.3. Прототипное наследование

JavaScript — объектно-ориентированный язык, но наследование в нём **прототипное** (prototypal inheritance), а не классовое в духе Java. У каждого объекта есть скрытая ссылка `[[Prototype]]` на другой объект — его прототип. При чтении свойства, которого нет в самом объекте, движок ищет его в прототипе, потом в прототипе прототипа — и так до `null`. Эта цепочка называется **цепочкой прототипов** (prototype chain).

```js
const task = { status: 'К выполнению' };
const prototype = {
  describe() {
    return `Задача «${this.title}» в статусе «${this.status}»`;
  },
};

const taggedTask = Object.create(prototype); // prototype стал прототипом
taggedTask.title = 'Написать тесты';

console.log(taggedTask.describe()); // метод найден в прототипе
console.log(taggedTask.hasOwnProperty('title'));   // true — своё свойство
console.log(taggedTask.hasOwnProperty('describe')); // false — из прототипа
```

Синтаксис `class` из ES6 — это не «другое наследование», а **синтаксический сахар** над прототипами. Методы класса попадают в объект `ИмяКласса.prototype`, а `extends` выстраивает цепочку прототипов.

```js
class Task {
  constructor(title, status = 'К выполнению') {
    this.title = title;
    this.status = status;
  }

  describe() {
    return `«${this.title}» — ${this.status}`;
  }
}

class DeadlineTask extends Task {
  constructor(title, deadline) {
    super(title); // вызов конструктора родителя
    this.deadline = deadline;
  }

  describe() {
    return `${super.describe()} (до ${this.deadline})`;
  }
}

const task = new DeadlineTask('Сдать отчёт', '2026-09-01');
console.log(task.describe()); // «Сдать отчёт» — К выполнению (до 2026-09-01)

// Цепочка: task → DeadlineTask.prototype → Task.prototype → Object.prototype → null
console.log(task instanceof Task);         // true
console.log(task instanceof DeadlineTask); // true
```

Зачем это знать, если фреймворки прячут детали? Три причины:

1. ошибки вида `Cannot read properties of undefined` и странные `this` почти всегда объясняются непониманием прототипов и контекста;
2. многие библиотеки (включая Vue с его системой реактивности) активно используют классы;
3. на собеседованиях по JS эта тема спрашивается с вероятностью, близкой к 100 % (проверено поколениями студентов).

> 💡 Полезно знать: `for...in` перебирает и унаследованные свойства, а `Object.keys()` — только собственные. Для проверки наличия свойства используйте `Object.hasOwn(obj, key)` (ES2022) вместо старого `hasOwnProperty` напрямую.

### 2.4. Деструктуризация, spread и rest

Эти возможности ежедневно экономят десятки строк кода, поэтому доведём их до автоматизма.

**Деструктуризация (destructuring)** — распаковка массивов и объектов в отдельные переменные.

```js
// Объекты: имена переменных совпадают с ключами
const project = { name: 'TaskFlow', owner: 'Анна', tasksCount: 42 };
const { name, owner } = project;

// Переименование и значения по умолчанию
const { name: projectName, priority = 'medium' } = project;

// Вложенные структуры
const board = {
  title: 'Спринт 6',
  columns: [{ id: 'todo', title: 'К выполнению' }],
};
const { columns: [firstColumn] } = board;
console.log(firstColumn.title); // «К выполнению»

// Массивы
const [first, second, ...others] = ['К выполнению', 'В работе', 'Готово'];
```

Особенно полезен паттерн **«объект параметров»** в сигнатурах функций: вместо positional-аргументов, порядок которых никто не помнит, функция принимает один объект и сразу деструктурирует его. Так написаны почти все API современных библиотек — и так мы будем писать в TaskFlow.

```js
function createTask({ title, deadline = null, tags = [], priority = 'medium' }) {
  return { id: crypto.randomUUID(), title, deadline, tags, priority, done: false };
}

createTask({ title: 'Настроить CI', priority: 'high' });
// дедлайн и теги подставятся по умолчанию
```

**Spread-оператор** (`...` в позиции значения) «разворачивает» коллекцию:

```js
const coreTags = ['срочно', 'баг'];
const allTags = [...coreTags, 'регрессия']; // объединение без мутации

const defaults = { theme: 'light', locale: 'ru' };
const userPrefs = { ...defaults, theme: 'dark' }; // { theme: 'dark', locale: 'ru' }
```

**Rest-оператор** (тот же синтаксис `...`, но в позиции приёма) собирает «остаток»:

```js
function logBoard(boardName, ...tasks) {
  console.log(boardName, tasks.length); // tasks — массив всего остального
}

const [winner, ...rest] = ['Деплой', 'Тесты', 'Документация'];
```

Запомнить просто: spread — когда мы **отдаём** элементы наружу, rest — когда **забираем** их внутрь.

> ⚠️ Частая ошибка: считать, что spread делает «полную копию» объекта. Копия **поверхностная** (shallow): копируются ссылки на вложенные объекты, и они остаются общими у оригинала и копии.

```js
const original = { title: 'Релиз', assignee: { name: 'Анна' } };
const copy = { ...original };

copy.assignee.name = 'Борис';
console.log(original.assignee.name); // «Борис» — вложенный объект общий!
```

Для глубокой копии используйте `structuredClone(value)` — встроенный механизм глубокого клонирования, доступный во всех современных браузерах и Node.js 17+.

### 2.5. Иммутабельность и чистые функции

Финальный и, возможно, самый важный раздел темы — он определяет архитектуру всего, что мы будем строить дальше.

**Чистая функция** (pure function) — функция, которая:

1. **детерминирована**: при одинаковых аргументах всегда возвращает одинаковый результат;
2. **не имеет побочных эффектов** (side effects): не изменяет аргументы, глобальные переменные, не пишет в консоль/сеть/файловую систему, не читает изменяемый внешний мир.

```js
// Чистая: результат зависит только от аргументов, ничего вокруг не трогает
const calculateProgress = (done, total) => (total === 0 ? 0 : done / total);

// Нечистая: читает и меняет внешнее состояние
let totalDone = 0;
const registerDone = () => { totalDone += 1; };
```

Метафора: чистая функция — это кухня, после которой не остаётся грязной посуды: ингредиенты вошли, блюдо вышло, ничего вокруг не испачкано. Нечистая функция — кухня, где повар одновременно готовит, отвечает на звонки и переставляет мебель.

Зачем это нужно в UI-приложениях:

- **тестируемость**: чистую функцию можно проверить, просто вызвав её с данными — без моков, DOM и базы;
- **предсказуемость**: состояние приложения меняется только явно, «невозможные» баги исчезают;
- **реактивность**: Vue, React и другие фреймворки строят оптимизации на сравнении ссылок. Если вы мутируете существующий объект, фреймворк может «не заметить» изменений;

**Иммутабельность** (immutability) — принцип, при котором данные не изменяются, а вместо изменения создаётся новая копия с нужными отличиями.

Сравните мутирующий и иммутабельный подходы на данных TaskFlow:

```js
const tasks = [
  { id: 1, title: 'Деплой', status: 'В работе' },
  { id: 2, title: 'Тесты', status: 'К выполнению' },
];

// ❌ Мутирующий подход
function markDoneMutating(list, id) {
  const task = list.find((t) => t.id === id);
  task.status = 'Готово'; // изменили объект внутри исходного массива
}

// ✅ Иммутабельный подход: новый массив с новым объектом
const markDone = (list, id) =>
  list.map((task) =>
    task.id === id ? { ...task, status: 'Готово' } : task
  );

const updated = markDone(tasks, 1);
console.log(tasks[0].status);   // «В работе» — оригинал не тронут
console.log(updated[0].status); // «Готово»
```

Шпаргалка по массивам: какие методы мутируют, а какие возвращают новый массив.

| Мутирующие (избегаем на общих данных) | Иммутабельная альтернатива |
| --- | --- |
| `push`, `pop`, `shift`, `unshift` | `[...arr, x]`, `[x, ...arr]`, `arr.slice(1)`, `arr.slice(0, -1)` |
| `splice` | `arr.toSpliced(...)` (ES2023) или комбинация `slice` |
| `sort`, `reverse` | `arr.toSorted(...)`, `arr.toReversed()` (ES2023) либо `[...arr].sort(...)` |
| прямое присваивание `arr[i] = x` | `arr.with(i, x)` (ES2023) или `arr.map(...)` |

Методы `map`, `filter`, `slice`, `concat`, `flat` и без того возвращают новый массив — они ваши лучшие друзья.

> 💡 Полезно знать: `Object.freeze(obj)` запрещает менять свойства объекта, но только на верхнем уровне (shallow freeze). В TypeScript тему иммутабельности продолжает модификатор `Readonly<T>` — мы вернёмся к нему в теме 4.

### Задание 1. Рефакторинг legacy-кода (~50 минут)

Ниже — фрагмент «древнего» трекера задач, написанный в 2013 году (все совпадения с реальными проектами закономерны). Ваша задача — отрефакторить его, сохранив поведение.

```js
// legacy.js — так писать больше не будем
var tasks = [];
var nextId = 1;

function addTask(title, deadline, priority) {
  var t = {};
  t.id = nextId;
  nextId = nextId + 1;
  t.title = title;
  t.deadline = deadline;
  t.priority = priority || 'medium';
  t.done = false;
  tasks.push(t);
  return t;
}

function getTasksByPriority(p) {
  var result = [];
  for (var i = 0; i < tasks.length; i++) {
    if (tasks[i].priority == p) {
      result.push(tasks[i]);
    }
  }
  return result;
}

function markDone(id) {
  for (var i = 0; i < tasks.length; i++) {
    if (tasks[i].id == id) {
      tasks[i].done = true;
    }
  }
}
```

Чек-лист рефакторинга:

## Контрольные вопросы

**1. Как работает замыкание?**

> Замыкание — это функция вместе с лексическим окружением, в котором она была создана. Когда внутренняя функция создаётся, движок сохраняет ссылку на переменные окружающих областей видимости; эта связь живёт, даже когда внешняя функция уже завершилась. Поэтому внутренняя функция продолжает читать и изменять «закрытые» в ней переменные: так реализуются приватное состояние (счётчики, таймеры в debounce) и фабрики функций. Важно: замыкание даёт доступ к самой переменной, а не к снимку её значения.

**2. В чём разница между `call`, `apply` и `bind`?**

> Все три метода явно задают контекст `this` функции. `fn.call(ctx, a, b)` вызывает функцию немедленно, передавая аргументы списком через запятую. `fn.apply(ctx, [a, b])` тоже вызывает немедленно, но принимает аргументы массивом — удобно, когда они уже собраны в массив. `fn.bind(ctx, a)` не вызывает функцию, а возвращает новую функцию с навсегда зафиксированным контекстом (и, опционально, частично применёнными аргументами) — её можно передать как колбэк, не потеряв `this`.

## Типичные ошибки и заблуждения

1. **`var` в цикле + замыкание.** Все колбэки видят одну переменную и печатают финальное значение. Лечится `let` (блочная область видимости создаёт отдельную переменную на итерацию).
2. **Потерянный `this` при отрыве метода.** `const f = obj.method; f()` вызывается без объекта слева от точки, и контекст исчезает. Лечится `bind`, стрелочной обёрткой или вызовом `obj.method()` на месте.
3. **Ожидание `this` от стрелочной функции.** У стрелок нет собственного контекста, `bind` на них не действует. Нужен управляемый `this` — используйте обычную функцию.
4. **Spread как «глубокая копия».** `{ ...obj }` копирует только верхний уровень; вложенные объекты остаются общими. Для глубокой копии — `structuredClone`.
5. **Мутация состояния «на месте» в UI-приложении.** `task.status = 'Готово'` может не запустить обновление интерфейса там, где сработало бы создание нового объекта. Привычка писать чистые функции, заложенная сейчас, сэкономит вам десятки часов отладки в темах про реактивность.
