# Тема 6. Инфраструктура проекта: Git, npm/pnpm, Vite, ESLint, Prettier

## Практическая часть

Практика превращает пустой каталог в учебный проект с «жёстким» инструментарием. Всё выполняется в терминале; результаты каждого шага видны сразу.

### Задание 1. Инициализация проекта и алиасы Vite (≈35 минут)

**Шаг 1.** Создайте проект из официального шаблона Vue + TypeScript:

```bash
pnpm create vite my-app --template vue-ts
cd my-app
```

**Шаг 2.** Инициализируйте Git по правилам из теории:

```bash
git init -b main
git add -A
git commit -m "chore: инициализация проекта"
git branch develop
git switch develop
```

**Шаг 3.** Добавьте алиас `@` в `vite.config.ts` (полный листинг — в разделе 6.3) и продублируйте его в `tsconfig.app.json`:

```jsonc
// tsconfig.app.json (блок compilerOptions)
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

**Шаг 4.** Проверьте: в `src/main.ts` замените импорт на `import App from '@/App.vue'`, затем запустите:

```bash
pnpm install
pnpm dev
```

**Ожидаемый результат:** dev-сервер стартует за доли секунды, приложение открывается на `http://localhost:5173`, импорт через `@/` работает без ошибок TypeScript.

**Шаг 5.** Зафиксируйте изменения коммитом `build: настройка алиасов Vite и tsconfig`.

### Задание 2. ESLint (flat config) и Prettier (≈35 минут)

**Шаг 1.** Установите инструменты:

```bash
pnpm add -D eslint @eslint/js typescript-eslint eslint-plugin-vue eslint-config-prettier prettier
```

**Шаг 2.** Создайте `eslint.config.js` (листинг из раздела 6.4) и `.prettierrc.json`, добавьте скрипты `lint` и `format` в `package.json`.

**Шаг 3.** Прогоните чистый проект:

```bash
pnpm lint
```

Ожидаемый результат: замечаний нет либо только косметика, которую исправит `--fix`.

**Шаг 4.** Провокация. Добавьте в любой компонент строку:

```ts
const провокация: any = 'проверка линтера';
```

Запустите `pnpm lint` — ожидаемый результат: ошибка `@typescript-eslint/no-explicit-any`. Уберите провокацию, прогоните `pnpm format` — Prettier должен выровнять код по `.prettierrc.json`.

**Шаг 5.** Коммит: `build: настройка ESLint и Prettier`.

### Задание 3. Husky, lint-staged и commitlint (≈30 минут)

**Шаг 1.** Установите пакеты и инициализируйте Husky:

```bash
pnpm add -D husky lint-staged @commitlint/cli @commitlint/config-conventional
pnpm exec husky init
```

**Шаг 2.** Запишите хуки (содержимое — в разделе 6.5), добавьте конфигурацию lint-staged в `package.json` и файл `commitlint.config.js`.

**Шаг 3.** Проверка №1 — плохое сообщение:

```bash
git add -A
git commit -m "поправил"
```

Ожидаемый результат: commitlint отклоняет коммит с подсказкой про допустимые типы.

**Шаг 4.** Проверка №2 — плохой код. Создайте `src/broken.ts` со строкой `const unused = 1;`, добавьте файл в индекс и повторите коммит с корректным сообщением. Ожидаемый результат: lint-staged не пропускает коммит из-за `no-unused-vars`. Удалите файл.

**Шаг 5.** Проверка №3 — всё по правилам:

```bash
git add -A
git commit -m "build: настройка git-хуков husky и lint-staged"
```

Ожидаемый результат: коммит создан, в логе `git log --oneline` — красивая история по Conventional Commits.

### Задание 4 (резерв). Задел под монорепо

Если осталось время, подготовьте структуру воркспейсов: создайте `pnpm-workspace.yaml` (листинг из раздела 6.2) и каталоги `apps/` и `packages/`, перенесите приложение в `apps/web` и выполните `pnpm install`. Это пригодится в теме 7.
