### Задание 2. Детектор среды исполнения (≈30 минут)

```bash
mkdir env-lab && cd env-lab
npm init -y
npm i -D typescript
```

Откройте `package.json` и добавьте `"type": "module"` — мы будем использовать ES-модули и в Node.js, и в браузере, что само по себе уже маленькая изоморфность.


**Шаг 1.** Создайте файл `src/runtime.ts` — модуль определения среды:

```ts
export type RuntimeKind = 'browser' | 'node' | 'webview' | 'worker' | 'unknown';

export interface RuntimeInfo {
  kind: RuntimeKind;
  hasDom: boolean;
  hasNativeBridge: boolean;
  globalObjectName: 'window' | 'global' | 'self';
}

/**
 * Определяет среду исполнения во время работы программы.
 * Использует только безопасные проверки: `typeof` не бросает
 * ReferenceError для необъявленных переменных.
 */
export function detectRuntime(): RuntimeKind {
  const g = globalThis as Record<string, unknown>;

  // 1. Node.js: есть объект process с таблицей версий.
  const proc = g.process as { versions?: Record<string, string> } | undefined;
  if (typeof proc === 'object' && proc !== null && proc.versions != null) {
    return 'node';
  }

  // 2. Web Worker: есть self, но нет document.
  if ('self' in g && !('document' in g)) {
    return 'worker';
  }

  // 3. Оконная среда: обычный браузер или WebView.
  if ('window' in g && 'document' in g) {
    // Capacitor добавляет глобальный объект Capacitor в нативном контейнере.
    return 'Capacitor' in g ? 'webview' : 'browser';
  }

  return 'unknown';
}

export function getRuntimeInfo(): RuntimeInfo {
  const kind = detectRuntime();
  return {
    kind,
    hasDom: 'document' in globalThis,
    hasNativeBridge: 'Capacitor' in globalThis,
    globalObjectName: kind === 'node' ? 'global' : kind === 'worker' ? 'self' : 'window',
  };
}
```

**Шаг 2.** Создайте файл `src/demo.ts`:

```ts
import { detectRuntime, getRuntimeInfo } from './runtime.js';

console.log(`Среда исполнения: ${detectRuntime()}`);
console.table(getRuntimeInfo());
```

Обратите внимание: импорт указывается с расширением `.js` — так требует система модулей Node.js, и это же корректно работает в браузере.

**Шаг 3.** Соберите и запустите в Node.js:

```bash
npx tsc src/runtime.ts src/demo.ts --target es2022 --module nodenext --outDir dist
node dist/demo.js
```

Ожидаемый результат:

```text
Среда исполнения: node
┌─────────────────────┬──────────┐
│ kind                │ 'node'   │
│ hasDom              │ false    │
│ hasNativeBridge     │ false    │
│ globalObjectName    │ 'global' │
└─────────────────────┴──────────┘
```

**Шаг 4.** Запустите тот же код в браузере. Создайте `index.html` в корне лаборатории:

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <title>TaskFlow — детектор среды</title>
  </head>
  <body>
    <h1>Откройте консоль DevTools (F12)</h1>
    <script type="module" src="./dist/demo.js"></script>
  </body>
</html>
```

Поднимите статический сервер и откройте страницу:

```bash
npx serve .
# затем откройте http://localhost:3000 в браузере
```

Ожидаемый результат в консоли DevTools: `Среда исполнения: browser`, `hasDom: true`, `globalObjectName: 'window'`. Один и тот же файл — две среды, два честных ответа.
