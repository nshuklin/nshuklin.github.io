# Тема 10. Маршрутизация и управление состоянием: Vue Router и Pinia

## Практическая часть

Контекст: приложение становится многоэкранным. Сегодня у него появятся страницы, «дверь с вахтёром» для приватных разделов и профиль, который не забывает себя при перезагрузке.

### Задание 1. Маршруты проекта и ленивая загрузка (~40 минут)

1. Установите зависимости:

```bash
npm install vue-router pinia
```

2. Создайте `src/router/index.ts` с маршрутами: `/` (главная со списком задач), `/login`, `/projects`, `/projects/:projectId` (канбан-доска), `/:pathMatch(.*)*` (страница «404: задача не найдена»). Все экраны, кроме главной, подключите через `() => import(...)`.

3. Зарегистрируйте роутер и Pinia в `main.ts`, добавьте в `App.vue` навигацию на `<RouterLink>` и `<RouterView />`.

4. Проверьте в DevTools → Network: при первой навигации на `/projects` загружается отдельный JS-чанк; при повторной — нет.

**Ожидаемый результат:** переходы работают без перезагрузки страницы, URL меняется, «назад/вперёд» браузера листают экраны, несуществующий адрес показывает страницу 404.

### Задание 2. Защита маршрутов через guard (~35 минут)

1. Создайте Setup store `src/stores/auth.ts` (образец — раздел 11.4): `token`, `user`, геттер `isAuthenticated`, действия `setSession` и `logout`.

2. Добавьте маршрутам `/projects*` мету `requiresAuth: true` и реализуйте глобальный `beforeEach`: без авторизации — редирект на `/login` с сохранением желаемого адреса в `query.redirect`.

3. Сделайте страницу входа: форма эмитит «успех» (для практики достаточно `setSession('demo-token', {...})`), после чего роутер возвращает пользователя на сохранённый адрес:

```ts
router.push(route.query.redirect?.toString() ?? '/')
```

4. Убедитесь: прямой заход на `/projects` без входа приводит на форму; после входа — на запрошенный экран.

**Ожидаемый результат:** «вахтёр» работает: неавторизованный пользователь приватные экраны не видит, но после входа попадает ровно туда, куда хотел.

### Задание 3. Профиль пользователя с персистентностью (~35 минут)

1. Создайте стор `src/stores/profile.ts`: имя пользователя, аватар-эмодзи, настройки (например, «показывать выполненные задачи»).

2. Реализуйте плагин `localStoragePlugin` из раздела 11.5 и подключите его к Pinia. Альтернатива: `$subscribe` прямо в компоненте профиля с `detached: true`.

3. Добавьте экран профиля (маршрут `/profile`), где поля редактируются и мгновенно сохраняются.

4. Проверка: измените имя, перезагрузите страницу (`F5`) — профиль на месте. Загляните в DevTools → Application → Local Storage и найдите ключ `app:profile`.

**Ожидаемый результат:** состояние профиля переживает перезагрузку; в Pinia DevTools виден стор и его изменения.

### Задание 4. `$patch` и `$subscribe` в действии (~10 минут)

1. В действии `logout` замените две записи на один `auth.$patch(...)`.
2. Подпишитесь `$subscribe` на стор auth и выведите в консоль тип мутации — посмотрите, как Pinia описывает каждое изменение.

**Ожидаемый результат:** выход из системы выполняется одной атомарной операцией; журнал мутаций нагляден.
